# Bacchat

A calm, private, open-source money notebook for mobile (Android first). It tracks net worth, goals,
spending and budgets, can read bank SMS and pasted emails to add transactions, and has an optional AI
advisor that runs on your own API key or on the phone itself. Everything runs on the device by default;
cloud sync is opt-in and end-to-end encrypted.

Built with React Native, TypeScript and Material 3 / Material You. Visual direction: "Khata", a ruled
household notebook.

## Repository layout

| Path | What it is |
| --- | --- |
| `frontend/` | The app: Expo (development builds), React Native, TypeScript. Own `package.json`. |
| `backend/` | "Bacchat Cloud", a small sync service that only stores encrypted blobs. Node, TypeScript, Docker. |
| `docs/` | Product, design system, screens, architecture, backend, testing, decisions, worklog, progress. |
| `CLAUDE.md` | Project guide for contributors and AI assistants (rules, conventions, design principles). |

Start with [docs/README.md](docs/README.md) for the documentation index.

## Prerequisites

| Tool | Version | Needed for |
| --- | --- | --- |
| Node.js | 20.19.4+ or 22.13+ (see `.nvmrc`) | everything |
| npm | bundled with Node | everything |
| JDK | 17 (Temurin or OpenJDK) | building the Android app |
| Android SDK | platform 36, build-tools 36.0.0, NDK 27.1.12297006, min SDK 24 | building the Android app |
| Docker | recent, with Compose | running the backend image (optional) |

You can run all the tests, typecheck and lint with Node alone. The Android SDK and JDK are only needed to
build and run the app on an emulator or phone.

### Arch Linux setup

```bash
sudo pacman -S --needed base-devel git unzip curl jdk17-openjdk nodejs-lts-jod npm docker docker-compose
sudo archlinux-java set java-17-openjdk
sudo systemctl enable --now docker && sudo usermod -aG docker $USER   # log out and in afterwards

mkdir -p ~/Android/Sdk/cmdline-tools && cd ~/Android/Sdk/cmdline-tools
curl -LO https://dl.google.com/android/repository/commandlinetools-linux-11076708_latest.zip
unzip commandlinetools-linux-*_latest.zip && mv cmdline-tools latest && rm commandlinetools-linux-*_latest.zip
cat >> ~/.bashrc <<'EOF'
export ANDROID_HOME=$HOME/Android/Sdk
export ANDROID_SDK_ROOT=$ANDROID_HOME
export PATH=$PATH:$ANDROID_HOME/cmdline-tools/latest/bin:$ANDROID_HOME/platform-tools:$ANDROID_HOME/emulator
EOF
source ~/.bashrc
yes | sdkmanager --licenses
sdkmanager "platform-tools" "platforms;android-36" "build-tools;36.0.0" "ndk;27.1.12297006" \
  "emulator" "system-images;android-35;google_apis;x86_64"
```

On other systems install the same versions with your package manager or Android Studio.

## Local development

### Frontend

```bash
cd frontend
npm install
npm run typecheck      # TypeScript, strict
npm run lint           # ESLint, zero warnings allowed
npm test               # Jest + React Native Testing Library (no device needed)
```

Run the app on an emulator or a USB-debugging phone (`adb devices` should list it):

```bash
npx expo run:android   # builds the dev client with all native modules, installs and starts Metro
npm start              # later: just start Metro for the installed dev client
```

Expo Go is not enough: the app uses native modules (SMS, share intent, OCR, SQLCipher, libsodium,
llama.rn, wallpaper colours). The `frontend/android/` project is generated by Expo; regenerate it after
changing native modules, plugins or `app.json`:

```bash
npx expo prebuild --platform android --clean
```

On first launch the app opens a local database seeded with sample data (a person called Rahul), so every
screen has something to show. Choose "Start fresh" on the Welcome screen for an empty notebook of your own, or "Look around with sample data" to keep the sample. Settings has "Clear sample data" and "Delete all data".

Optional app config in `frontend/app.json` under `expo.extra`:

| Key | Meaning |
| --- | --- |
| `cloudUrl` | Default Bacchat Cloud address (empty means users type their own server). |
| `googleClientId` | Google OAuth client id for Drive sync. See [docs/decisions.md](docs/decisions.md). |
| `npsNavUrl` | Default NPS NAV source (can be changed in Settings). |

### Backend

```bash
cd backend
npm install
npm run typecheck && npm run lint && npm test
DATA_DIR=./data npm run dev          # http://localhost:8080, SQLite in ./data
npm run demo                         # 45-check walkthrough of every feature, in-process
```

With Docker:

```bash
docker compose up --build            # port 8080, data in the named volume bacchat-data
curl localhost:8080/healthz
DEMO_URL=http://localhost:8080 npm run demo     # run the walkthrough against the container
```

Point the app at your server in Settings, Backup and sync. Environment variables, the API and
self-hosting notes are in [backend/README.md](backend/README.md) and [docs/backend.md](docs/backend.md).

### Using the AI features

Open Settings and pick a mode under AI: off, your own API key (Anthropic or any OpenAI-compatible
endpoint, including self-hosted Ollama or LM Studio), on this phone (download a small model), or auto.
The advisor only ever sees totals. For SMS and email parsing in cloud mode the text is masked first and
needs your one-time consent. See [docs/architecture.md](docs/architecture.md).

## Before you commit

Run the checks for the side you changed and do not commit on a red build:

```bash
cd frontend && npm run typecheck && npm run lint && npm test
cd backend  && npm run typecheck && npm run lint && npm test
```

Commit messages are short, single-line and describe one step. Keep `docs/worklog.md` and
`docs/progress.md` current. Text in code, docs and commit messages is plain ASCII (the rupee sign lives
in sample data and strings, and is written as the escape `\u20B9` in source). More rules are in
[CLAUDE.md](CLAUDE.md).

## Status

All 29 screens are built and wired to a local encrypted database, the sync client and the AI advisor,
with 1,650 frontend tests and 37 backend tests passing. Native Android code (Kotlin modules, Gradle
builds for llama.rn and libsodium) has been written but not yet compiled on a device. Current
progress, known gaps and open decisions are in [docs/progress.md](docs/progress.md).
